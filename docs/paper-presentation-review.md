# Paper presentation regression review

The preferences acceptance run [38233978513](https://github.com/wieslawsoltes/ReportScene/actions/runs/38233978513) failed one of 42 browser scenarios: the full-paper test sampled RGB (195,195,195) at (700,800) immediately after desired layout reported full paper. The six new preferences scenarios and the other 35 existing scenarios passed, but this was not complete acceptance.

A read-only inspection of the retained trace and PNG ([review run 38241757421](https://github.com/wieslawsoltes/ReportScene/actions/runs/38241757421)) found that the failure-hook screenshot already contained RGB (255,255,255) at exactly (700,800), with white paper through the surrounding lower-page region. The recorded state progressed from a new desired compact layout while RenderCount remained 1, to desired full paper with RenderCount 2. Publishing .NET layout is not a guarantee that its later WebGL frame has been presented. This evidence supports an asynchronous pixel-observation race, not a persistent incorrect full-paper extent; it does not establish a GPU latency or throughput measurement.

The regression now observes real browser screenshots until the same strict sample condition is met, within the existing assertion deadline. No input is replayed, no application state is modified by the check, and no failing test is automatically retried. The original coordinates and white (>245 in all RGB channels) and gray (<230 in all channels) thresholds are unchanged. The scenario additionally tests two complete compact/full/compact cycles, retains screenshots and the sampled pixels, and asserts unchanged source paper dimensions, content revision and history before continuing all original page editing, undo, validation and export assertions.

This is a test synchronization correction, not a claimed application renderer fix or a reason to waive visual failures. A persistent gray full-paper frame still fails. All four browser shards, the complete 42-scenario gate, native and actual WebAssembly conformance, desktop and independent package consumers remain mandatory before merge. The temporary inspection workflow is absent from the final source tree.

Reference: [Playwright polling assertions](https://playwright.dev/docs/test-assertions#expectpoll). The polling callback captures a fresh actual screenshot; it does not reuse the expected model or synthesize pixels.
